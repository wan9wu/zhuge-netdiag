# 诸葛网络问题诊断器（zhuge-netdiag）

一个用 Rust 编写的开源网络问题自动诊断工具，面向 Windows 10/11。提供**命令行版**（`zhuge-netdiag.exe`）与**图形界面版**（`zhuge-netdiag-gui.exe`）两个可直接运行的程序，功能完全一致。

它会自动检测当前电脑的网络环境，找出本机到公网的完整链路，**逐级检查链路中每一个节点的连接情况**，经过深入分析后指出**网络瓶颈出在哪个环节**——是本地 Wi-Fi/网线、路由器、运营商接入段、DNS 服务器，还是应用层代理配置的问题，并给出具体的修复建议。不只测"通不通"，还能量化"好不好"：分段测量丢包率与时延，告诉你丢包究竟严重在哪一环。

## 诊断流程（全自动 7 步）

1. **本地环境**：枚举网卡 / IPv4 / 网关 / DNS，选定主用链路
2. **网关连通性**：ping 网关 + ARP 交叉验证 + TCP 采样测本地段质量
3. **公网可达性**：IP 直连多个公共节点 + TCP 采样测端到端质量
4. **DNS 解析**：按协议直查系统/公共 DNS，区分"断网"还是"DNS 失效"
5. **逐跳链路**：traceroute 逐跳统计丢包与时延，定位坏节点
6. **应用层 HTTP**：多端点探测，识别代理/防火墙/Web 认证问题
7. **综合分析**：多证据交叉验证，输出瓶颈定位结论与修复建议

## 特性

- **零配置自动诊断**：自动枚举网卡、IPv4 地址、默认网关、DNS 服务器，挑选主用链路
- **网关连通性检查**：量化本机到网关的丢包率与时延（Wi-Fi 信号差、路由器过载在这里现形）
- **公网可达性检查**：直连多个公共 DNS 节点 IP，排除 DNS 因素判断互联网连通性
- **DNS 解析检查**：按 DNS 协议直接向系统 DNS 与公共 DNS 发送查询，区分"网络不通"还是"DNS 失效"
- **逐跳链路探测**：基于 IP TTL 的 ICMP 逐跳探测（traceroute），每一跳发送多个探测包，统计逐跳丢包率与时延
- **网络质量测量**：不只测连通性——分段采样丢包率与时延（网关段 / 公网节点 / 端到端），对比定位丢包严重的环节；采样次数可自定义（默认 20 次，可调到 100 次以上捕捉间歇性丢包）；ICMP 被屏蔽时自动改用 TCP 采样（反复 TCP 握手测 RTT 与丢包），依然能给出质量数据
- **瓶颈定位引擎**：自动识别丢包率过高、时延突增、链路中断等问题，定位到具体环节（本地网络段 / 运营商网络 / 目标侧 / DNS / 应用层）
- **应用层检查**：HTTP 探测识别代理配置错误、防火墙拦截、Web 认证（强制门户）
- **诊断报告**：控制台结论 + 自动保存 Markdown 报告文件，方便发给运营商报修
- **两种界面**：命令行版适合脚本/自动化场景；图形界面版（基于 egui）提供参数设置、实时进度、彩色结论卡片与报告保存/复制
- **无需管理员权限**：使用 Windows 系统公开文档化的 ICMP API（icmp.dll），不依赖原始套接字

## 使用的开放协议

本项目只使用公开的标准互联网协议，不依赖任何私有协议或闭源服务：

| 环节 | 协议 | 标准 |
|---|---|---|
| ping / 逐跳探测 | ICMP Echo / Time Exceeded | RFC 792 |
| 链路发现 | IP TTL 递减机制 | RFC 1812 |
| 域名解析测试 | DNS over UDP | RFC 1035 |
| 应用层测试 | HTTP/1.1 | RFC 9110 |
| 质量采样（ICMP 被屏蔽时） | TCP 握手时延/丢包采样 | RFC 9293 |
| 网关在线交叉验证 | ARP | RFC 826 |

## 快速开始

### 图形界面版（推荐）

双击运行 `zhuge-netdiag-gui.exe`，在顶部设置诊断目标（IP 或域名）、探测次数、超时与最大跳数，点击"开始诊断"。诊断在后台线程进行，"实时日志"页签展示逐步进度；完成后可在"诊断报告"页签查看彩色结论卡片与完整报告，并可保存到文件或复制到剪贴板。

### 命令行版

将编译好的 `zhuge-netdiag.exe` 复制到任意目录，打开"终端"或"命令提示符"：

```
zhuge-netdiag.exe
```

### 常用参数

```
zhuge-netdiag                          # 默认诊断（目标 223.5.5.5）
zhuge-netdiag --target www.baidu.com   # 指定诊断目标
zhuge-netdiag --count 10               # 每跳探测 10 次（更精确）
zhuge-netdiag --samples 100            # 质量采样 100 次（长时间测丢包）
zhuge-netdiag --quick                  # 快速模式
zhuge-netdiag --report C:\报告.md       # 指定报告保存路径
zhuge-netdiag --help                   # 查看完整帮助
```

## 从源码编译（Windows 11）

1. 安装 Rust 工具链（二选一）：
   - MSVC：安装 Visual Studio Build Tools（C++ 工作负载）+ [rustup](https://rustup.rs)
   - GNU：安装 MinGW-w64（如 WinLibs），然后 `rustup toolchain install stable-x86_64-pc-windows-gnu`
2. 编译：

```
cargo build --release
```

3. 产物：`target\release\zhuge-netdiag.exe`（命令行版）与 `target\release\zhuge-netdiag-gui.exe`（图形界面版），均为单文件，可直接复制到任何 Windows 10/11 电脑运行，无需安装运行时。若只需命令行版，可用 `cargo build --release --no-default-features` 跳过 GUI 依赖。

## 诊断报告解读

程序结束时输出形如：

```
==============================================================
                         诊断结论
==============================================================
  [正常] 本机网络接口：适配器 "WLAN"（Wi-Fi）已获得 IPv4 192.168.1.5/24
  [正常] 本机→网关：网关 192.168.1.1 连通良好 ...
  [异常] 逐跳链路：第 3 跳 10.20.1.1（运营商网络）丢包 45%
         建议：问题在运营商网络内，本地链路正常，建议向运营商报修并附上本报告
--------------------------------------------------------------
  >> 瓶颈定位：第 3 跳 10.20.1.1（运营商网络）丢包 45%
==============================================================
```

瓶颈结论按以下优先级自下而上判定：

1. **本机网络接口**：没有可用网卡/IPv4
2. **本地网络配置**：缺少默认网关
3. **本地网络段**：网关不可达或丢包 >5%、时延 >50ms（Wi-Fi、网线、路由器问题）
4. **运营商接入链路**：网关正常但公网全部不可达
5. **逐跳链路**：某一跳丢包率过高（≥20%）或时延突增（相对上一跳翻倍且差值 >30ms）、链路中断
6. **网络质量**：TCP 采样分段对比——本地段丢包严重（≥20%）定位本地链路；本地段良好但端到端丢包高则定位运营商/目标侧
7. **DNS**：系统 DNS 失效（公共 DNS 正常时给出更换建议）
8. **应用层**：IP 层连通但 HTTP 失败（代理、防火墙、Web 认证）

### 防误报：多证据交叉验证

很多路由器/运营商会屏蔽 ICMP（ping 全丢但上网正常）。本工具不会单凭一种探测手段下结论：

- 网关不回应 ping → 用 **ARP** 验证网关是否在线
- 公网 ping 全丢 → 用 **TCP 采样**、HTTP、DNS 结果交叉验证可达性
- 只有 ICMP 与 TCP **双双失败**才判定故障；ICMP 被屏蔽的网络会明确提示"不影响上网"

## 常见问题

**Q: 需要管理员权限吗？**
不需要。ping 与逐跳探测基于 Windows 公开的 ICMP API（icmp.dll），普通用户即可运行。

**Q: 某些跳显示 `*`（无应答）？**
很多路由器被配置为不回应 ICMP Time Exceeded。只要其后的跳可达，`*` 不代表丢包，程序会自动识别并标注。

**Q: 逐跳探测显示某跳丢包很高，但上网没感觉？**
中间节点常对 ICMP 做限速，造成"假丢包"。程序会结合其后各跳的状态综合判断，报告中会提示该可能性。

**Q: 支持 IPv6 吗？**
当前版本聚焦 IPv4 诊断；IPv6 支持在路线图中，欢迎提交 PR。

**Q: 支持 Linux / macOS 吗？**
当前版本仅支持 Windows（ICMP 探测依赖 Windows 系统 API），跨平台移植欢迎贡献。

## 路线图

- IPv6 链路与 DNS AAAA 查询
- TCP/UDP 端口级探测（针对 ICMP 被整体过滤的网络）
- 带宽 / 速率测试
- 持续监测模式（后台轮询、记录劣化时段）

## 项目结构

```
src/
├── lib.rs        核心库入口（CLI 与 GUI 共享）
├── runner.rs     7 步诊断流程编排
├── env.rs        本地网络环境检测（网卡/IP/网关/DNS）
├── icmp.rs       Windows ICMP API 封装（无需管理员）
├── trace.rs      ping 统计与 traceroute 逐跳探测
├── arp.rs        ARP 链路层交叉验证
├── quality.rs    TCP 采样质量测量（丢包/时延）
├── dns.rs        DNS 协议手工实现（RFC 1035）
├── http.rs       HTTP 应用层多端点探测
├── diagnose.rs   瓶颈定位引擎（多证据交叉验证）
├── report.rs     Markdown 诊断报告生成
├── main.rs       命令行版入口
└── bin/
    └── zhuge-netdiag-gui.rs   图形界面版入口（egui）
```
